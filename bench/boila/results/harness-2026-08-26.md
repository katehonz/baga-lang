# harness — P27 sequential ladder (2026-08-26)

`bench/boila/harness.baga`: single-thread SQL path през `boila_server_exec`
(sync server). Same machine as this session (point read is slower than
the 2026-08-09 scorecard — hardware, not a regression of the SQL path).

P27: fsync only dirty shards; LSN counter lives on those shards
(`boila_put_at`), not a hashed sys key that forced a second WAL.

Insert stays ~1 fsync (~1.4 ms) as shard count grows. Pre-P27 would
fsync all 4 WALs (~250 ops/s estimated).

## Честен вердикт

- **1 fsync / auto-commit statement** is the floor while
  `synchronous_commit` is on. 5–10k ops/s needs a commit window or
  delayed durability — residual, not this phase.
- Group commit of many rows in one statement is unchanged (already
  30× vs sync-per-row in `insert_write`).
