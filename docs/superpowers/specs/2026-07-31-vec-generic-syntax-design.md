# `Vec<T>` в типовите анотации — Дизайн

> Дата: 2026-07-31. Статус: одобрен (auto mode). Продължение на typed-vec.

## Идея

`Vec<T>` става валиден тип навсякъде, където тип може да се пише: параметри,
`let` анотации, връщани типове, spec input/output. Чисто адитивно — `Vec`
без параметър си остава валиден със сегашната семантика (неизвестен елемент,
`vec_get` → i64 fallback).

```baga
fn сума(v: Vec<i64>) -> i64 {
    let mut s: i64 = 0
    for i in 0..vec_len(v) {
        s += vec_get(v, i)     // i64 — от анотацията, не от push
    }
    return s
}

spec сума {
    input:
        v: Vec<i64>
    output: i64
    ensures:
        output >= 0 || output < 0   // винаги вярно; демо
}
```

## Семантика

- **Парсер:** след `Vec` в типова позиция, незадължителен `<тип>`. Представяне:
  NODE_TYPE с `type_name = "Vec"` и `inner_type` = вътрешния тип (същото union
  поле, което REF/ARRAY ползват — съвместимо).
- **resolve_type_node:** `Vec` → TYPE_VEC; с `inner_type` → `elem` = resolve-нат
  вътрешен тип. Елементите остават ограничени до i64/str — друго → грешка
  `Vec<T>: неподдържан елементен тип <T> (поддържат се i64 и str)`.
- **type_eq за Vec:** ако и двата имат `elem` и се различават → не са равни;
  ако някой няма `elem` → равни (обратна съвместимост, `Vec<i64>` минава за
  `Vec` параметър и обратно на ниво съвпадение на сигнатури).
- **Взаимодействие с checker-а:** параметър `v: Vec<i64>` влиза в env с elem —
  `vec_get(v, i)` връща i64, `vec_push(v, "s")` е грешка. Spec проверката
  (която ползва type_eq) приема `Vec<i64>` срещу `Vec<i64>`.
- **Codegen (C + LLVM):** игнорират `inner_type` — представянето е същото
  (`baga_Vec *`); изборът на helper си остава по `elem` от типа на аргумента.

## Извън обхвата

- Обща проверка на типовете на аргументите при извикване на потребителски
  функции (отделна фича — засяга всички типове, не само Vec).
- Vec<f64>/Vec<struct> runtime.

## Приемливост

- Позитивен: `fn сума(v: Vec<i64>)` + `vec_get` връща i64; `vec_push` със str
  върху него → грешка. И през двата backend-а.
- Негативен: `Vec<f64>` → грешка за неподдържан елементен тип.
- `Vec<str>` параметър + `vec_get` → str, print работи.
